# ADR-0002 — Local sets, language editions, finish profiles and release events

**Status:** accepted design and executable dry-run; authoritative migration pending
[#140](https://github.com/m4s-ai/snoredex-data/issues/140) ·
**Issue:** [#146](https://github.com/m4s-ai/snoredex-data/issues/146) ·
**Parent:** [#132](https://github.com/m4s-ai/snoredex-data/issues/132) ·
**Depends on:** [#145](https://github.com/m4s-ai/snoredex-data/issues/145)

This decision adds the catalogue layer above ADR-0001's card releases. It changes no current
consumer identity and creates no card release. The raw input registry is
[`set_catalogue_sources.json`](set_catalogue_sources.json), the executable SQLite contract is
[`set_catalogue_schema.sql`](set_catalogue_schema.sql), and the rebuilt graph is
[`set_catalogue_dryrun.json`](set_catalogue_dryrun.json), generated by
`python scripts/set_catalogue_dryrun.py`.

## Problem boundary

`setCode`, marketplace languages and one scalar release date cannot identify a physical Pokémon
TCG set. The same provider label may be reused in several localities, a broad editorial release
may have different local names, codes and card pools, and one local edition may launch in several
markets or waves. Finish availability has the same shape: a set statement can be language-scoped,
conditional on rarity or number, and carry explicit exceptions.

The old Snorlax projection is also the wrong discovery boundary. A provider-visible set is useful
even when no Snorlax is known in it. Requiring a row in `snorlax_cards.json` before admitting the
set would make the catalogue unable to discover what it was built to find.

## Accepted graph

- `source_record` is an immutable provider row with its raw identifier and values.
- `set_concept` is an optional editorial relationship. It is never a card-identity shortcut.
- `local_set` is one set, deck, promo series or product family in one locality. Its provider code
  is unique only with that locality.
- `set_edition` is one printed language/script edition of a local set. Language, script and market
  locality remain separate values.
- `release_event` carries date value, precision, approximation, status, timezone and explicit
  market scope. Editions link to events; dates never live on a set concept.
- `finish_profile` carries language-bearing edition links, sourced rules, conditions, exceptions,
  precision and any justified closure scope.
- `card_release_ref` points only to a release already established by ADR-0001. Set availability,
  finish profiles and rarity claims have no path that can mint one.
- `rarity_claim` belongs to a card release and preserves the source-native vocabulary. Cardmarket
  and Bulbapedia claims are distinct rows even when their normalized meaning agrees.
- aliases and edition relationships are provenance-bearing edges. Reused raw identifiers start as
  candidates; they do not imply cross-locality equivalence.

The SQL contract uses foreign keys, uniqueness checks and scoped value checks for these nodes and
edges. It also prevents updates or deletes of a loaded source record. #140 may choose a different
physical layout, but it must preserve the same boundaries and constraints.

## Evidence and closure rules

Positive evidence can create a local set, edition, event or finish rule only at the scope the
source states. Silence creates neither an event nor a negative claim. An unknown date remains a
`needs-evidence` disposition unless a dated/undated event itself is positively identified.

A finish profile establishes a finish only for card releases that already belong to one of its
linked editions. Its conditions are evaluated after reachability; they are not a set checklist.
Closure is legal only when both a closure scope and an accepted complete-manifest or equivalent
explicit complete-statement authority are recorded. The Skyridge rule therefore closes only the
question “is a reverse-holo version available?” inside English, German and Italian, with H/32
excluded. It does not close the card's complete finish list.

A physical specimen remains independent card-level evidence. A specimen showing a treatment that
falls outside a closed profile is a reported conflict; neither source overwrites the other.

Rarity can imply a base finish only through a declared, sourced vocabulary mapping. It can never
establish that a card or language edition exists. A marketplace rarity attached to a listing from
another locality is retained as a held source claim rather than projected onto that local release.

## Source registry and accounting loop

Decision D1: set discovery reads `set_catalogue_sources.json`, not Snorlax membership. The initial
registry contains all 135 observed legacy `(setCode, setName)` profiles, five source-first local
codes, 45 reviewed release-date rows and two edition-availability rows. The seed pass under
`verification/passes/` is historical migration code; recurring builds read only the committed
registry. #147 can append provider records through reviewed passes before a card-release mapping
exists.

Every source record receives exactly one reversible disposition: `mapped`, `matched`, `related`,
`positively-excluded`, or `needs-evidence`. The build reports collisions, possible false merges,
orphans, scalar-date loss, finish-scope loss and held cross-locality rarity claims, then validates
the entire result by loading it into an empty in-memory SQLite database. A run is acceptable only
when every input is accounted for, all foreign keys hold and all adversarial fixtures pass.

## Compatibility projection

Current consumers may continue to read their existing `setCode`, `setName`, language and scalar
date fields until #140. That projection is explicitly lossy:

- a raw code without locality can collide;
- one language list hides distinct language/script editions and regional Spanish releases;
- one date loses market, wave, precision, approximation, status, timezone and source;
- one finish list loses language scope, exceptions, conditions, closure authority and conflicts;
- one rarity column destroys independent provider claims and cross-locality divergence;
- source-first sets disappear when the projection begins from Snorlax cards.

The dry-run publishes these losses as data. No compatibility field is allowed to become evidence
for a new catalogue node.

## Consequences

The graph is larger than a flat set table, but independent facts no longer overwrite one another.
Shared events and set concepts remain possible through explicit edges. AS5a can relate to Japanese
source material without becoming an `sm10` language; identical `sv10` strings in several markets
remain separate; and releases in different waves keep their own dates.

Authoritative ids and consumer tables remain deferred to #140. Catalogue ingestion and source
coverage can proceed in #147, and alias/equivalence review can proceed in #148, against this
versioned boundary without waiting for that migration.
