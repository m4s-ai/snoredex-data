# ADR-0001 — Locality-aware physical print identity

**Status:** proposed · **Issue:** [#134](https://github.com/m4s-ai/snoredex-data/issues/134) ·
**Parent:** [#132](https://github.com/m4s-ai/snoredex-data/issues/132) ·
**Depends on:** [#133](https://github.com/m4s-ai/snoredex-data/issues/133)

The schema before the migration, because #134 asks for it in that order and the order is right:
once consumers read new ids, the old shape stops being a choice and becomes a compatibility
promise. Nothing here changes a store. The machine-readable form is
[`print_identity_schema.json`](print_identity_schema.json); the measured consequences are in
[`print_identity_dryrun.json`](print_identity_dryrun.json), regenerated by
`python scripts/print_identity_dryrun.py`.

## Context

Identity today is Cardmarket's. A card is `(setCode, number, variantToken)` read off a product
page, and **language is an attribute of that product**. `verification/units.json` keys a unit as
`(setCode, number, variant, language)`, which looks like it carries a locality dimension but does
not: the set code and collector number in that tuple always belong to the product Cardmarket
listed, never to the localized printing the claim is about.

So a Korean Snorlax is recorded as *the Korean language of a Japanese product*. It has a Korean set
code and a Korean collector number in the real world, and this repository has never held either,
because there was nowhere to put them.

The dry run measures how much of the catalogue that is:

| | |
|---|---:|
| Legacy product-variant nodes | 196 |
| Print nodes after a locality split | **358** |
| Products that split across more than one locality | **64** |
| Print nodes whose own set code and number are unknown | **172** |
| — Korean | 64 |
| — Traditional Chinese | 62 |
| — Indonesian | 20 |
| — Thai | 19 |
| — Simplified Chinese | 6 |
| — Japanese | 1 |
| Specimens the owner holds with no catalogue node at all | **8** |

172 of 358 print nodes are printings this project has evidence for and cannot name. 112 of the
underlying claims are `confirmed` — positive outside evidence that the printing exists — so this
is not a queue of doubtful rows. It is the catalogue's own knowledge, filed under someone else's
identifiers.

One product carries four separate physical printings under one identity:

```
Korean      claim -> node sv2a 181 (Japanese market), url Snorlax-V2-sv2a181
T-Chinese   claim -> node sv2a 181 (Japanese market), url Snorlax-V2-sv2a181
Indonesian  claim -> node sv2a 181 (Japanese market), url Snorlax-V2-sv2a181
Thai        claim -> node sv2a 181 (Japanese market), url Snorlax-V2-sv2a181
```

And eight physical cards the owner has photographed have no node whatsoever:

```
SPEC-0007  sc1b F   120/153   T-Chinese      SPEC-0011  sc1a F   127/154   T-Chinese
SPEC-0008  sc1b F   177/153   T-Chinese      SPEC-0014  S-P      101       Korean
SPEC-0009  sc1b F   119/153   T-Chinese      SPEC-0015  sc?? F   111/159   T-Chinese
SPEC-0010  sc1b F   165/153   T-Chinese      SPEC-0024  AS5a     142       T-Chinese
```

[`CATCHUP-SETS.md`](CATCHUP-SETS.md) reached this conclusion from the evidence side already and
states the principle this ADR formalizes: *a catch-up reprint is a distinct product with its own
set code and number, not a `language` attribute of the overseas slot.* It is the same finding, one
layer down.

The failure the whole of #132 opens with — the missing Traditional Chinese `svQP F 012/023` — is
this shape. Nothing in the current model has a place to put it.

## Decision

Model the catalogue as **works** and **prints**, with locality and language as separate dimensions.

A **print** is one physical localized printing, keyed by
`(locality, localSetCode, localNumber, variant)`. That tuple is its identity. **The Cardmarket
product becomes an alias edge onto the print, not the print's name.**

Nodes are `work`, `print`, `locality`, `language`, `script`, `local_set`, `source_record` and
`alias`; edges are typed and carry provenance. The full definitions, with cardinalities, live in
[`print_identity_schema.json`](print_identity_schema.json) so that a check can read them.

### The invariants that matter

1. **`language != locality`.** No consumer derives one from the other. Spanish spans WEST and
   LATAM; English spans WEST and SEA.
2. A print has exactly one `(locality, localSetCode, localNumber)` within its local set.
3. Prints sharing a work are still distinct prints — `sm10 076` and `AS5a 142` share artwork and
   are two printings.
4. An alias never erases a raw local identifier. `svQP` and `svQPF` both survive on the edge.
5. Records merge only through an explicit, provenance-bearing equivalence decision. Never on
   matching name, number or artwork.
6. Finish, variant and error classification may not create or erase a regular print identity.
7. **`localSetCode` and `localNumber` are null exactly when `localIdentifierKnown` is false.**

Seven is the one that keeps this honest, and it is enforced by the dry run today. The tempting
shortcut is to let a Korean print inherit `sv2a 181` because that is where the claim was found.
That would manufacture a Korean set code that does not exist, and it would be indistinguishable
from a real one a year from now. A null is a stated gap. The 172 nulls are the discovery queue
[#138](https://github.com/m4s-ai/snoredex-data/issues/138) works.

### What does not change

- **The evidence model.** Authority tiers, `providerId`, `corroborated`, `absenceScopes` and owner
  adjudications are untouched. This ADR changes what a claim is *about*, never what makes it true.
  A print with no evidence is an absent node, not a claimed one — `pending` still means not yet
  established, never proven absent.
- **Existing verdicts.** All 719 migrate with their evidence. None is re-derived; re-deriving is
  how you lose the ones resting on owner attestation, which no database records.
- **The legacy baseline** (#133). The migration adds a disposition per member rather than
  rewriting a frozen artifact.

## Migration contract

Reversible, and dry-run first. Every legacy member carries exactly one disposition — `carried`,
`split`, `aliased` or `queued` — and a member with none fails the dry run. The current run leaves
nothing unaccounted: 196 products, 719 language units and 75 excluded code-card claims all have
one, with 0 unresolved units.

A **back-projection** must reproduce the legacy shape from the graph. That is what makes the
migration reversible in the sense that matters: if the projection cannot rebuild the old file, the
mapping lost something, and the mapping is wrong rather than the old file obsolete.

Migration itself is [#140](https://github.com/m4s-ai/snoredex-data/issues/140). This ADR and its
dry run are what that issue needs before it can start.

## Consequences

- The checklist grows. A Korean printing behind a Japanese slot becomes its own collectible row,
  and 172 of those rows will initially say "we know this exists and not what it is called". That
  is more honest than the current silence, and the metric polarity already treats a rising
  documented count as progress.
- `market` on a card becomes derived rather than stored: it is the locality of its prints.
- Consumers keep working through compatibility projections until #140 retires them. No consumer is
  asked to infer locality from a language label, which is #134's closing condition.
- Eight orphan specimens get somewhere to live, which is the first thing the owner will notice.

## Open questions for the owner

These are the collector's call, not the schema's, and `CATCHUP-SETS.md` already lists them per
code: whether each catch-up code (`AS5a`, `sc1a`/`sc1b`, `FXY`, `S-P`, `SV-P`) enters the catalogue
as its own product now, or waits for a per-code adjudication.

The schema represents either outcome without a rewrite, because an absent print is an absent node
rather than a false one. The decision changes when the rows appear, not whether the model can hold
them.
